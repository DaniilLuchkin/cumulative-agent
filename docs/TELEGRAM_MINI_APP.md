# Telegram Mini App — Мои задачи

Готовый интерфейс в стиле Reminders встроен в существующий FastAPI сервис.
Отдельные frontend server, сборщик, React, Redis и отдельная БД не нужны.
Открывается по `/app` (также `/`); прежний read-only dashboard доступен по `/dashboard`.

## Что доступно

* Создание, просмотр и редактирование задач: название, детали, проект, дедлайн,
  приоритет. Четыре уровня (0/10/20/30) и своё число от −1000 до 1000.
* Фильтры: активные, сегодня, просроченные, завершённые, отменённые и фоновые. Поиск по
  названию/описанию с поддержкой русского регистра, фильтр проекта, пагинация.
* Сортировка по приоритету, дедлайну, дате создания или последнему изменению.
* Выбор даты/времени, быстрые «Сегодня», «Завтра», «Без срока». Даты учитывают
  часовой пояс устройства, включая дни перехода на летнее время; сервер хранит
  timezone-aware значения. Изменение одного приоритета не округляет исходный срок.
* Галочка «выполнено» и возврат вручную завершённых задач. Новую задачу можно
  передать агенту или оставить напоминанием (`inbox`) без LLM-вызова.
* Из карточки напоминание передаётся агенту; очередную задачу можно приостановить.
  Видны статус, результаты предыдущих запусков и ожидание зависимостей/ресурсов.
* Отмена выполняемой задачи, явный повторный запуск отдельной задачей, история
  изменений, этапы выполнения, защищённое скачивание patch/report и оценка результата.
* Повторения каждый день/неделю/месяц и Telegram-напоминания до срока/при просрочке.
  Обычный текст с распознанной датой или повторением сначала подтверждается в чате.
  `/timezone Europe/Moscow` задаёт часовой пояс разговорного ввода.
* Адаптивный mobile/desktop интерфейс, Telegram light/dark theme, native BackButton
  закрывает редактор. При возвращении в приложение список обновляется.
* Минималистичные строки задач, нейтральная палитра, тонкие разделители.
* Вкладка «Ресурсы»: OpenRouter и другие зарегистрированные providers, модели и
  capabilities, Telegram Bot API, состояние CPU/RAM/disk; цены input/output за 1М
  токенов, остаток/лимит token quota, reset, context/output/rate limits, дневной и
  фоновый бюджеты, стоимость/timeout/concurrency одного запуска.

На desktop «Ресурсы» находятся в sidebar; на телефоне — в кнопке рядом с названием.
Данные обновляются раз в 15 секунд, а также кнопкой «Обновить». Раскрытые лимиты
моделей сохраняются при refresh. API credentials никогда не показываются.

Квоты, цены и budgets из registry/config и локального учёта показаны отдельно от
наблюдений OpenRouter `/key` и `/models` с временем проверки. Кнопка сверки API ставит
задачу обновления метаданных; автоматическая проверка включается `resource_auto_sync`.
Наблюдения не меняют разрешённые модели, бюджеты и настроенные цены: изменение цены
блокирует модель до проверки YAML. Неизвестный остаток обозначен «Не отслеживается».
«Настроен» означает наличие adapter, а не проверенный live API health. В бюджет
включены running reservations даже до предыдущей полуночи. Manual quota update
остаётся доступным через API; новые accounts не регистрируются.

Дедлайн — срок выполнения, а не отложенный старт. Агент может начать ready task
раньше дедлайна. Уведомления отправляются владельцу через Telegram Bot API и
durable outbox, когда сервис работает; повторения создаются после завершения
предыдущего экземпляра. Подробности: [PROJECT_WORKFLOWS.md](PROJECT_WORKFLOWS.md).
Сортировка списка не отменяет scheduling rules: user tier
всегда выше background, а scheduler учитывает дедлайн и доступные ресурсы.

## Подключение к боту

Нужен публичный HTTPS endpoint на том же сервере. Домен необязателен: установщик
поддерживает доверенный сертификат Let's Encrypt на публичный IPv4 и URL
`https://ВАШ_IP/app`; см. [OPERATIONS.md](OPERATIONS.md). Адрес localhost через SSH tunnel
подходит для обычного браузера, но не для Telegram на телефоне.

1. Разместите обновлённый сервис на Ubuntu; обычный HTTP upstream оставьте
   `127.0.0.1:8000`. Подготовленный [Nginx пример](../deploy/nginx-miniapp.conf.example)
   использует ваш домен и существующий TLS certificate. Автоматического deployment,
   изменения firewall или получения сертификата в этой задаче не выполнялось.
2. В secrets/environment сервиса укажите:

   ```ini
   TELEGRAM_BOT_TOKEN=<your-existing-bot-token>
   TELEGRAM_OWNER_IDS=<your-user-id>
   TELEGRAM_CLAIM_FIRST_USER=false
   TELEGRAM_WEBAPP_URL=https://tasks.your-domain.com/app
   ```

   Вместо env URL можно задать `telegram_webapp_url` в YAML. Только HTTPS;
   credentials, query и fragment в адресе запрещены. URL не является секретом.
   Для автоматической первой привязки вместо IDs: `TELEGRAM_OWNER_IDS=` и
   `TELEGRAM_CLAIM_FIRST_USER=true`. Сразу отправьте боту `/start`: первый private
   text update назначает владельца в SQLite. Mini App само владельца не назначает;
   сохранённый ID проверяется тем же ACL в API и чатах. Явная allowlist в config/env
   имеет приоритет; её можно задать для восстановления доступа без удаления БД.
3. Перезапустите сервис. В личном чате с ботом отправьте `/app`: появится кнопка
   «Открыть мои задачи», и для вашего чата настроится menu button «Мои задачи».
   `/start` и `/help` также показывают кнопку. Чаты не из allowlist её не получают.
4. Нажмите кнопку. В Telegram пароль/token вводить не нужно: API проверит подпись
   `Telegram.WebApp.initData`, время её выпуска и user ID в owner allowlist.

BotFather не обязателен: chat menu button устанавливается через Bot API после
`/app`. При желании тот же URL можно указать как menu button в настройках бота.
Не используйте обычную ссылку как замену Web App button: вне Mini App Telegram
signed initData отсутствует, и будет показан обычный браузерный вход.

## Вход через браузер

Откройте `http://127.0.0.1:8000/app` локально или через SSH tunnel и введите
`AGENT_API_TOKEN`. Он хранится только в памяти страницы; reload требует входа
заново. Не вставляйте token в URL. Данные задач недоступны без авторизации.

Telegram HMAC session по умолчанию действует час с `auth_date`; после истечения
закройте и снова откройте приложение из кнопки бота. Настройка:
`telegram_init_data_max_age_seconds` (60..86400). Сервер никогда не доверяет
`initDataUnsafe` или переданному из браузера user ID без подписи.

## Сохранность данных

Редактор передаёт `expected_updated_at`: если задачу изменили параллельно,
сервер ответит 409 и предложит открыть её заново. Содержание выполняемой или
завершённой задачи защищено от подмены; дедлайн и приоритет можно исправлять.
Checkbox не завершает running task и опасные proposals, не создаёт фиктивного
agent run, не запускает действие. Возобновить автоматически выполненную задачу
галочкой нельзя. Старые tasks/DB совместимы — новые поля имеют defaults.
Тексты и результаты отображаются через textContent, без выполнения HTML.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
node tests/test_task_utils.mjs
PYTHONPATH=src python3 tests/smoke_browser.py
```

Browser acceptance использует development-only Playwright + Chromium, реальные
HTTP-запросы и mock Telegram SDK с корректно подписанным synthetic initData.
Playwright установлен в dev execution environment, не требуется production image.
Для воспроизведения в отдельном dev окружении установите `playwright` и выполните
`python -m playwright install chromium`. Тест не вызывает реальные Bot API/LLM.
